## 第二阶段：色彩策略作用于整块区域

### 已采用的决策

- 策略从「放大色阶 C 倍数」改为「决定哪些区域有颜色、占多大面积、前景与背景是什么关系」。区域角色固定为 brand（品牌主区域）、auxiliary（辅助内容区域）、canvas（画布本身）。
- 策略与区域构成：克制=近中性品牌区，不铺画布；投入=一个完整品牌区；全色板=品牌区 + 辅助内容区（邻近色相，色相 +32°）；浸染=画布自身染色 + 更深的品牌区。
- 进入区域后局部重映射语义变量（背景、表面、文字、边框、行动、焦点环、功能色），同一按钮/输入框/链接自动适配；画布层保留品牌行动色，只换表面与文字。
- 区域内的主行动不再与背景同色：品牌区用与背景分离的表面色（亮色区域用深色行动、深色区域用浅色行动），克制策略保留品牌强调色。
- 次要文字从区域前景与背景的关系推导（向背景靠一档），要求 WCAG ≥ 4.5 或 APCA ≥ 60。
- 功能色在染色区域单独生成一档，保留成功/警告/错误/信息语义，不作为分区或装饰色。
- 面积比例是策略建议而非硬指标；区域位置与拓扑由内容重要性决定。

### 实施证据

- `node --test tests/regions.test.cjs`：4 项通过。覆盖 8 个品牌色（亮蓝、浅黄、深紫、高彩度品红、接近成功色、接近错误色、近中性灰蓝、暖橙）× 4 策略 × 2 主题的区域配对，全部在**最终 Hex（含色域裁剪）**上验证：正文 ≥ 4.5、次要文字 ≥ 4.5 或 APCA ≥ 60、行动 ≥ 3、行动文字 ≥ 4.5、边框 ≥ 1.6、功能色 ≥ 3。
- 缩小页面观察 `stage-2/` 同一页面四张截图：克制为中性画布 + 蓝色行动；投入为大面积品牌首屏；全色板为蓝色品牌区 + 淡紫辅助区；浸染为整页染色画布 + 深蓝品牌区 + 同色系浅色卡片。数据、排版与结构在四张截图中完全相同。
- 工作台：仅「转化趋势 · 近 8 周」报告面板上色，其余面板保持中性，图表随区域前景转为白色；不存在为凑比例染色每个面板的情况。
- 亮色品牌（`#f59e0b`）、深色品牌（`#4c1d95`）、接近成功色（`#16a34a`）的营销页与流光暗色页面均已渲染检查；区域文字、行动与边框在实测配对下可读。
- 导出：CSS 含 48 个区域变量与 `.ce-region-*` 局部映射类；组件导出给出同一控件在普通区域与彩色区域的用法；提示词新增「区域配色」段；JSON 携带区域配对色与功能色；Tailwind 暴露 `region-*` 颜色键。

### 残留限制

- 区域边界与后续内容的过渡在营销页用圆角区块处理，未做全出血色带；需求侧可以按内容需要选择区块或整屏表达。
- 图表等自带配色的 SVG 只随区域前景变量变化，未做完整的区域内数据可视化配色系统。

## 生成对照：同一需求、独立上下文

### 方法

- 需求固定为 `brief.md`（澄禾知识库营销页 + 工作台），品牌固定 `#2563EB`。
- 三组都在全新隔离上下文、不读取彼此输出的条件下生成，使用同一继承模型与同一需求：
  - `ai-baseline/`：实施前引擎的导出上下文。
  - `ai-stage-1/`：第一阶段的上下文。
  - `ai-final/`：当前（三阶段完成）的上下文，`/tmp/ce-ai/context.md` 为同一份提示词导出。
- 对照结论基于 1280×900 渲染截图与 390px 视口溢出检查。

### 结果

| 项目 | 结论 | 画面证据 |
|---|---|---|
| 营销页首屏 | 改善 | 原版为白底 + 蓝色按钮的通用结构；当前版本用整块品牌区域承担首屏，标题、正文与主要行动都在区域内，主要行动用区域内浅色按钮保持可辨 |
| 工作台区域配色 | 改善 | 只有「继续阅读 / 最近更新」区域上色并承担重点内容，其余面板保持中性；未出现整屏彩色或每个面板都染色 |

| 功能与文案质量 | 持平 | 由需求侧决定，两组均满足 brief 的功能与事实约束 |

### 第二份需求复核（阅读 + 展示）

- 需求：`/tmp/ce-ai/brief2.md`（青冈工作室：一篇 1200 字中文长文 + 4 件作品展示），品牌色 `#0f766e`，同样在全新隔离上下文中生成，产物在 `ai-final-brief2/`。
- 用途选择：阅读页 `data-ce-mode="read"`、展示页 `data-ce-mode="experience"`——两页的主要任务不同，AI 自行判断而非套用同一模式。
- 区域配色：阅读页只在页首标识区用品牌区域，正文、目录、引用、表格与脚注保持中性；展示页只在页尾行动区用品牌区域，作品本身占据主位。符合“阅读页面低干扰、展示页让作品决定画面”的规则。
- 品牌色处理：需求给的 `#0f766e` 与导出 CSS 中预置的色阶不同，AI 按上下文的**角色关系**（强调色、悬停、淡底、焦点环、区域配对色）重新推导了整套色阶，没有手工挑零散颜色。
- 排版：表头、表格数字与作品年份使用数据角色与 `tabular-nums`，标签与表格未使用展示字体；正文行宽与行距符合阅读用途。
- 结论：营销 / 操作 / 阅读 / 展示四种任务均由 AI 按上下文自行判定并应用了对应规则，未要求用户补充设计判断。

### 残留风险

- 品牌区域面积较大时，需求侧内容偏少会显得空；提示词已写明面积是策略建议、区域位置由内容重要性决定。
- 两份需求的生成结果都是一次通过，未做同一需求的多次采样；结论按“单次对照”记录，不作为稳定提升的统计结论。

## 第三阶段：做实中文排版

### 已采用的决策

- 字体角色分四类：中文展示、中文正文、拉丁展示、数字数据。同一字体可承担多个角色，五种风格不各用一套字体。
- 交付顺序为「平台原生中文字体优先，Noto 作为确定回退」：`PingFang SC / Hiragino Sans GB / Microsoft YaHei / Songti SC` 是各平台自带、渲染成熟的中文字体，不是碰巧安装的字体；`Noto Sans SC`、`Noto Serif SC`（OFL-1.1）作为跨平台兜底与可选品牌展示字体，通过 `@font-face` 交付，缺失时回退原生栈。
- 字形分工（关闭颜色后仍可辨认的部分）：书卷用宋体衬线（`Songti SC` / `Noto Serif SC` / `SimSun`）；暖糖用人文无衬线（`Hiragino Sans GB` 优先，字面更宽、字腔更开）；流光用细字重 + 放宽字距；光谱与标准用几何无衬线（`PingFang SC`），字距略有差别。拉丁展示与数据字体按风格区分（Avenir Next / Helvetica Neue / Georgia / SF Mono / Menlo）。共 3 种中文字形（几何无衬线 / 人文无衬线 / 宋体衬线）+ 字重字距差异，未强行为五种风格各配一套字体。
- 排版角色：展示标题、页面标题、区块标题、正文、标签与控件、辅助说明、数据与代码；每个角色给出字体、字重、字号、行高、字距、行宽与换行策略。
- 中文行宽按全角字控制：阅读用途 34em（约 28–34 个全角字/行），不直接套用英文 65–75ch。阅读正文行高 1.9，操作正文 1.6。
- 标点与换行：`text-spacing-trim`、`hanging-punctuation` 处理行末标点，标题 `text-wrap: balance` 避免单字末行，正文 `text-wrap: pretty`，不依赖写死 `<br>`。
- 数字在表格、指标、时间记录中统一 `tabular-nums`。
- 操作页面沿用稳定角色字号，展示字体不进入标签与数据（`[data-ce-mode="operate"]` 将 `--ce-display` 指向正文字体）。

### 实施证据

- 字体实测（macOS 15，Chrome）：`PingFang SC / Hiragino Sans GB / STHeiti / Songti SC / STSong / Avenir Next / Helvetica Neue / Georgia / Menlo` 可用；`SF Pro Rounded / Segoe UI / Microsoft YaHei / Noto Sans SC / Noto Serif SC / Bahnschrift` 不可用。因此**四种无衬线风格的中文字形此前实际都落到 PingFang SC**，风格差异主要来自字重、字号、字距与 CSS 效果；书卷落到 Songti SC，是唯一由字形产生的风格差异。本阶段据此把中文字形差异交给「衬线 / 无衬线」两档 + 可选的 Noto 展示字体，不再假装五种风格各有中文字形。
- 计算样式实测（书卷阅读页）：标题 `36px / 650`，正文 `17px / 32.3px`（1.9），行宽 `578px`（34em）；字体栈中中文字体在拉丁字体之后按序回退。
- `node --test tests/typography.test.cjs`：4 项通过，覆盖字体角色完整性、中文回退顺序、排版角色字段、字体进入全部出口、操作页面不引入展示字体。
- `stage-3/` 含 8 组样例：书卷阅读亮/暗、标准营销、标准工作台、暖糖展示、流光暗色工作台、光谱营销、亮色品牌的浸染营销。关闭颜色差异后，标题尺度、行宽与段落节奏仍能区分用途。
- `stage-3/type-only-styles.html`：把五种风格的同一句中文标题、同一段正文、同一组数字放在纯灰度、无装饰的页面上直接比较。可辨认的是：书卷（衬线）、暖糖（人文无衬线、字面更宽）、流光（细字重、字距放宽）；光谱与标准同为几何无衬线，差异主要来自字距与后续用途规则。这是本阶段能达到的上限，若要五种风格各有中文字形，必须自托管第三方字体。
- 字重实测：`PingFang SC` 在 200/300/400/500/600/700 上渲染出明显不同的笔画粗细，流光的细字重成立。
- 长中文标题、中英数字混排（`API`、`CSV`、`128.4k`）、括号标点、表单标签与按钮文案均在样例中出现并检查；`type-only-styles.html` 另含生僻字串（龘齉爨蠡彧燚犇淼鑫垚烜翀翾蘅懿曦），未出现缺字方框。
- 窄屏检查：`stage-2` 与 `stage-3` 全部样例在 390px 视口下 `scrollWidth` 等于视口宽度、无元素越界（此前一次“截断”是 Chrome 无头窗口最小宽度 485px 造成的截图假象，已改用 iframe 真视口复测）。

### 残留限制

- `stage-3/export-only.html` + `export-only.css`：只引用导出产物、不引入工具自身 demo 样式搭出的干净页面，书卷衬线、中文行宽、数据等宽数字与品牌区域内的行动按钮均按预期呈现，区域类在没有工具样式的环境下同样生效。这验证的是“导出产物自洽”，不等于在另一台机器上验证过。
- Windows / Android 的实际中文字形未在本环境验证，仅按系统字体名给出回退顺序。
- 可选品牌展示字体未随仓库提供二进制文件（完整 CJK 字体体积大）；`@font-face` 导出给出 OFL 授权、获取地址、`unicode-range` 与自托管方式，缺失时按原生栈回退，不影响布局与阅读。
- 中文圆体（暖糖风格）在平台字体中无对应字形，当前回落无衬线；如需严格圆体需自托管第三方圆体并接受体积。
